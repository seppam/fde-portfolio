# Evaluation report

Golden set: 30 fictional POs (11 PDF, 12 handwritten photos, 7 Excel), 186 lines,
10 scenario POs (unknown product, discontinued, credit limit, duplicate, prompt
injection, price mismatch, missing PO number, unit not sold, quantities as words,
outlier quantity). Generated by `scripts/gen_golden.py` with the correct answers.

Models: `gemini-3.5-flash-lite` (PDF and photos), `openai/gpt-oss-120b` on Groq
(Excel and the matching tie-break), temperature 0. All raw results are in
`experiments/` (one JSON per run, `history.csv` for the trend).

## Results

| Metric | Run 1 (baseline) | Run 3 (final) | Final, without LLM tie-break |
|---|---|---|---|
| Customer correct | 93.3% | **100%** | 100% |
| PO number correct | 83.3% | 96.7% | 96.7% |
| Date correct | 100% | 100% | 100% |
| Lines found | 100% | 100% | 100% |
| SKU correct | 92.5% | **92.5%** | 82.8% |
| Qty + unit correct | 99.5% | 99.5% | 99.5% |
| Expected checks raised | 88.9% | **100%** | 90% |
| False checks | 22 | **0** | 4 |
| Silent errors (wrong SKU, no warning) | n/a | **0** | 0 |
| POs needing zero edits | 43.3% | **53.3%** | 30.0% |

Tokens per PO (average): ~1,070 in / ~460 out. Average extraction time without
cache: 20.5 s (measured in run 2, the last run with uncached calls; free tier, during a
period of 503 "high demand" answers).

## What changed between runs, and why

Run 1 surfaced problems in **both** the agent and the test data. Both were fixed,
and the reasons are recorded so nobody "tunes to the test":

| Finding | Kind | Fix |
|---|---|---|
| "Toko Bintang Abadi" vs "Toko Abadi Bintang": two real customers, matcher ignored word order | agent | word order counts; city / contact break ties |
| Handwritten "C015" read as "CO15", so a resent PO was not caught as duplicate | agent | normalised PO key (case, spaces, "No." label, O vs 0) |
| "minyak goreng surya emas" with no size reported as *unknown product* (13 of the 22 false flags) | agent | new `AMBIGUOUS_VARIANT` check listing the sizes; shop history picks the size it always buys |
| PO number labels included the word "No." | test data | generator fixed |
| 9 false credit-limit flags: synthetic shops had unrealistically small credit | test data | master data fixed (normal shops have headroom) |
| PO with 500 cartons was also over credit, the label only expected the outlier | test data | label completed |

## What is still not good enough

- **Zero-edit rate 53% (target 60%).** Of the 14 POs that need an edit, 13 contain
  a line where the shop did not write the size. The agent flags them correctly and
  never guesses. Two ways to close the gap, both outside code: ask the client to
  add sizes to the shared order template, or let shop history accumulate (the
  history rule only works after a shop's first approved order, and in this set most
  shops order once).
- One handwritten PO number lost a character ("PO/031" instead of "PO/C031").
- Status: only 7 of 30 POs come out *ready*; LLM tie-break matches are marked for a
  quick look by design (confidence 0.75 < 0.9). This trades admin clicks for safety.
